# 写真から似た1本を薦める機能 — 設計

2026-09-16 / ブランチ `renewal` / 対象 https://drtbeer.com

## 1. なぜ作るか

AdSense の審査に2回落ちた。2回目の理由は「有用性の低いコンテンツ」で、実測した原因は
**200ページの平均146字・最短12字という、テンプレートで埋めた紹介文**だった。
文章を増やして審査を通すこともできるが、それは「広告を載せるために記事を書くサイト」を
作ることであり、元の動機ではない。

そこで上流に戻って3点を整理した。

| 問い | 答え |
|---|---|
| ① クラフトビールの課題 | **一度飲んで好きだった1本の「次」が分からない**。銘柄が多すぎ、スタイル名は初心者に読めない |
| ② どう解くか | **好きだった1本の写真を撮ると、似た1本を薦める** |
| ③ 誰から金をもらうか | **蔵から**。①自サイトのPR枠 ②蔵のサイトに置く分析ウィジェットと月次レポート |

広告は収益源から外す。**サイトの価値は「薦めの質」であり、それを売る相手は蔵である。**

## 2. 範囲

**作る**: 写真の受け取り → 銘柄の同定 → 類似の推薦 → 匿名での蓄積 → 蔵向けの計測。

**作らない**(意図的に):

- 検索機能(既存の一覧ページがある)
- レビュー・点数投稿(Untappd と正面衝突し、監査の仕組みも使えない)
- お気に入り・フォロー等の SNS 機能
- スマホアプリ(ダウンロードの壁が高すぎる)

既存の products / maker / style の3テーブルと、銘柄・蔵・スタイルの各詳細ページは**そのまま使う**。

## 3. 画面の流れ

```
[トップ] 飲んで良かった1本を撮る
   ↓ 写真をアップロード(またはカメラ起動)
[判定中] 生成AIに画像を渡す(2〜5秒)
   ↓
[結果] ┌─ 銘柄を特定できた → その銘柄として扱う
       └─ 特定できない   → 読み取れたスタイル・色を出し「これで合っていますか」
   ↓
[推薦] 似た3件 + その下に「PR」枠
   ↓ 気に入った1件をタップ
[銘柄ページ] 既存の詳細ページ(味覚マップ・蔵の情報)
```

トップは**読み取りから始まる**。既存の Beer / Brewery / Type の一覧は**タブとして残す**。
3Dの銀河(Flavour Galaxy)は「位置づけの地図」として残すが、**推薦の根拠には使わない**。

### 同定できなかったときの分岐

| 状態 | 画面の反応 | 裏でやること |
|---|---|---|
| DBにある銘柄だと特定 | その銘柄として扱う | `upload` に記録 |
| 銘柄名は読めたがDBに無い | 「まだ登録されていません」+ 読み取れたスタイルで推薦 | `unknown_beer` に記録 |
| 銘柄名も読めない | 「スタイルは◯◯に見えます。合っていますか?」と確認を求める | 確認結果を記録 |
| ビールに見えない | 撮り直しを案内。バーコードを撮る選択肢も出す | 記録しない・画像も保存しない |

3行目が肝で、**外したときに黙って誤った推薦を出さず、ユーザーに確認させる**。
推薦の質とデータの質が同時に上がる。

### 蓄積の見え方

- 1回目・2回目: ログインを求めない。結果は端末に残り、固有URLを発行する
- 3回目: 「記録を残しますか」と **LINE ログイン**を案内(Google は後から足す)
- ログイン後: 過去に撮った銘柄の一覧が見られる

LINE ログインは無料。Messaging API による通知は有料(200通/月まで無料、以降
¥5,000/5,000通)だが、**今回は通知を使わないので費用は発生しない**。

## 4. データの持ち方

既存3テーブルには触らず、5つ足す。

| テーブル | 持つもの | 何のため |
|---|---|---|
| `visitor` | 匿名ID、初回訪問日、(紐づいたら)LINEのユーザーID | 人の識別。**LINE連携は列を1つ埋めるだけ**で過去の記録が繋がる |
| `upload` | 匿名ID、画像、判定結果(銘柄ID または null)、読み取ったスタイル・色、確度、使ったモデル、画像ハッシュ | 1回の撮影 |
| `unknown_beer` | 読み取れた銘柄名、回数、最終日時 | **次のデータ投入バッチの優先リスト** |
| `recommendation` | どの upload に対して、どの3件を、どの段階の理由で出したか。PR枠に何を出したか | 何を薦めたかの記録。蔵への報告の根拠 |
| `event` | 匿名ID、種別(表示 / クリック / PRクリック / 確認への回答)、対象 | 行動そのもの |

### 個人情報の扱い

- 匿名IDは **Cookie(1年)**。氏名・メールは取らない
- LINE からも**ユーザーIDだけ**受け取る(表示名・アイコンは取らない)
- 写真は**保存する**。公開面には一切出さず、本人の履歴でのみ表示する
- 蔵に渡すのは**集計値のみ**。個人単位のデータは渡さない

### 注意

`event` は放っておくと最も大きくなる(1人1回の利用で5〜10行)。
いまの RDS で問題になるのはかなり先だが、**古いイベントの集計・圧縮**をいずれ考える。

## 5. 推薦ロジック

実データを調べたところ、単純な「同じ系統から選ぶ」は2か所で破綻する。

- **`IPA` に 73銘柄(全体の36%)** — 系統で絞っても73件から3件を選ぶことになり、絞り込みにならない
- **同じ StyleID に他がいない銘柄が23件** — 系統だけでは推薦が0件になる

| 同スタイルの件数 | スタイル数 | 該当銘柄 |
|---|---|---|
| 1件(仲間なし) | 23 | 23 |
| 2〜4件 | 27 | 73 |
| 7件以上 | 10 | 104 |

### 4段のカスケード

上から順に候補を集め、**3件に達したら止める**。

| 段階 | 条件 | 意味 |
|---|---|---|
| 1 | 同じ `StyleID` | 最も近い(American IPA どうし) |
| 2 | 同じ `FamilyName` の別スタイル | 系統は同じ(American IPA → Hazy IPA) |
| 3 | 同じ**表示グループ**(ipa / pale / stout / wheat / sour / other) | ゆるく近い |
| 4 | 度数が近いもの | 最後の手段 |

段階2〜3が「仲間なし23件」を救い、段階1が「IPA 73件」を細かいスタイルに割る。

### 並べ替え

同じ段階の中では、この順:

1. **別の蔵を優先** — 同じ蔵ばかり並ぶと「次の1本」にならない
2. 度数が近い順
3. 同点なら新しく登録された順(新しい銘柄が埋もれない)

### ホップによる加点は入れない

`products` に原材料・ホップの列がない。ホップ品種は gitignore 下の事実カードにしかなく、
記録のある銘柄とない銘柄が混在している。**今回は段階1〜4だけで作り、
列の追加とデータ投入は次のデータバッチで並行して進める。** 後から加点として足せる設計にする。

## 6. 画像判定

**モデル: Claude Sonnet 5**(`claude-sonnet-5`)。PHP から Anthropic SDK
(`composer require anthropic-ai/sdk`)で呼ぶ。APIキーは `db_config.local.php` と同じ方式で、
`api_config.local.php` を gitignore + サーバ内で注入する。送信前に長辺1568pxへ縮小。

Haiku 4.5 は半額(約0.4円/枚)だが、**この機能の成否は日本語ラベルを読めるかに尽きる**ため、
まず Sonnet 5 で出す。精度が十分だと分かってから落とす。

### 返させる項目(構造化出力 `output_config.format` で固定)

| 項目 | 用途 |
|---|---|
| `is_beer` | ビール以外を弾く |
| `brand_text` / `brewery_text` | ラベルから読めた文字(そのまま) |
| `matched_product_id` | DB200銘柄から1つ、無ければ null |
| `style_guess` | 102スタイルから1つ、無ければ null |
| `color` (1-10) / `clarity` (1-4) | 液色から。DB未該当でも推薦を回せる |
| `confidence` (0-1) | 下の分岐に使う |

**200銘柄の一覧はプロンプトの前半に固定してキャッシュする**(呼ぶたびに再送しない)。
一覧が変わるのはデータ投入のときだけなので、キャッシュが効く。

### 確度による分岐

| 確度 | 挙動 |
|---|---|
| 0.8 以上 | 「〇〇ですね」と1件表示して確認1タップ |
| 0.4〜0.8 | 候補3件を出して選ばせる |
| 0.4 未満 | DB未該当として `unknown_beer` に記録し、`style_guess`/`color` だけで推薦 |

### 費用の見積もり

1枚あたり約0.8円(画像1枚 + 一覧キャッシュ + 出力200トークン、¥150/$換算)。

## 7. 蔵向けの提供物(収益②)

### ウィジェット — 恒久無料

```html
<script src="https://drtbeer.com/w/v1.js" data-beer="pr0123"></script>
```

- その銘柄に似た3本を表示。A1のカスケードをそのまま使う
- **並びは蔵向けに反転させる**: 自蔵の近い銘柄を先、残りを他蔵から。
  競合だけを出すウィジェットは誰も貼らない
- 「Powered by Darth Beer」リンクで自サイトへ流入(SEOと入口を兼ねる)
- 表示回数・クリックを `event` に記録

**収益源ではなく流入装置**として位置づける。無料にするほど貼られ、貼られるほど
こちらにデータと客が来る。

### 月次レポート — 月3,000円/蔵(データが貯まるまでは無料)

- その蔵の銘柄が何回アップロードされたか、確度と読み取り失敗率
- 併愛マップ = その銘柄を上げた人が他に何を上げたか(自蔵/他蔵)
- どのスタイルの層に選ばれているか
- **需要の空白** = 探されているのに登録が無い銘柄(`unknown_beer` から)

最後の1つは蔵にとっても価値がある。「御社の△△は月20回探されているのに、
当サイトに情報がありません」は掲載を勧める根拠になる。

## 8. PR枠(収益①)

### 置き方

- 推薦3本の**下に1枠だけ**。カード左上に「PR」
- **推薦アルゴリズムには一切混ぜない。** 順位も候補も動かさない。
  **推薦を返す関数と PR枠を返す関数をコード上も分ける**
- リンク先は蔵の公式ページ。表示回数・クリックは `event` に記録し、月次レポートで返す

### 何を出すか

アップロードされたビールの**表示グループ**を買っている蔵の銘柄1本。
複数あればローテーションで均等配分。**該当ゼロなら枠ごと出さない**(空きを埋めない)。

### 料金

**スタイルグループ枠の月額固定。** 例: IPA枠 月5,000円、1グループ最大3蔵までローテーション。
インプレッション課金・クリック課金は採らない — 初期トラフィックでは請求の手間が売上を上回り、
クリックを増やす誘惑が推薦の中立性を侵す。

### ステマ規制(景表法 2023-10-01)

「PR」表記に加えて、利用規約と about に
「掲載料を受け取った枠であること」「推薦順位には影響しないこと」を明記する。

### 規模感

6グループ × 3蔵 × 5,000円 = 月9万円(年108万)。月次レポートの144万と合わせて
**年250万が天井**の商売である。増やすなら枠を増やすのではなく、
掲載できる蔵の母数(= 登録銘柄数)を増やす。

## 9. 失敗と不正の扱い

### APIを呼ぶ前に弾く(費用防衛の本体)

- 形式と容量(jpeg/png/webp、10MB以下)、サーバ側で長辺1568pxに縮小
- **画像ハッシュで再送を検出** → 同じ写真はAPIを呼ばず前回の結果を返す
- バースト制限 1分3枚 / 訪問者1日20枚 / 全体1日200枚
- **暦月あたり4,000枚(約3,200円)で自動停止**、以降は手動再開
- 環境変数ひとつで機能全体を止められるようにする(障害・暴走時の最終手段)
- dev は**別カウンタ・別枠(1日30枚)**。開発中の試行で本番の枠を食わない

### 結果ごとの扱い

| 結果 | 挙動 |
|---|---|
| `is_beer=false` | 「ビールの写真に見えませんでした」+再アップ導線。**画像は保存しない**。5回続いた訪問者は当日の枠を絞る |
| DBに無い銘柄 | `unknown_beer` に記録し、スタイルと色だけで推薦は出す |
| API失敗(5xx/タイムアウト) | 再試行は1回まで。駄目なら「混み合っています」+手動検索へ |

## 10. テスト方針

既存の特性テストハーネス(`tests/`、28ケース)に足す。新しい枠組みは入れない。

| 対象 | やり方 |
|---|---|
| 推薦カスケード | 固定データで単体テスト。**4段すべてに到達する入力**を用意する — 同StyleIDに候補あり / StyleIDに1件しかない(実際に23銘柄) / IPA 73件からの絞り込み / 度数NULL |
| **PR枠の中立性** | 同じ写真に対し、PR契約を「なし/あり/3蔵あり」と変えて、**推薦3本が1ビットも変わらないこと**。必須項目 |
| 画像判定 | 実APIは叩かない。**記録と再生** — 一度だけ実行した応答JSONを保存し、以降は再生。`is_beer=false`・確度中・確度低・API失敗の4系統 |
| 門番と上限 | 境界を見る。20枚目は通り21枚目は弾く / 同一ハッシュはAPIを呼ばない / 停止フラグで全部止まる |
| 蓄積 | 匿名で貯めた履歴が、後からLINEで紐づけたときに引き継がれること |

### 同定精度の検証(前倒し)

当初は公開後に作る判断だったが、**正解データが揃ったので実装に含める**。

- 入力: `data/sample/` の写真15枚(gitignore)と `data/sample/expected.json`(追跡する)
- 採点: `brewery` と `product` の一致。`is_beer=false` の2件は門番が効いたかだけを見る
- 内訳: DBに銘柄がある4 / 蔵はあるが銘柄が無い5 / 蔵も無い4 / ビールではない2
- 難所: 缶の裏面のみ・曲面で先頭文字が欠ける・暗所の黒缶・ドイツ語の `ß`・ロゴだけで蔵名がない
- 同一銘柄が2枚(`IMG_4816` / `IMG_4817`)あるので、**画像ハッシュではなく銘柄として一致させられるか**も測れる
- 1回の実行は約12円(15枚 × 0.8円)。モデルやプロンプトを変えたときに回す

## 11. デザイン

現行の Nebula(紫の地 `#0b0820` + マゼンタ→バイオレット→ティールのグラデーション)を捨て、
**黒地・写真主役の「露光」**に置き換える。
モック: `docs/design-mocks/D_exposure.html`(スマホ3画面 + 色見本)。
旧案の `B_nebula.html` はこれで置き換わる。

### 変えること

| | |
|---|---|
| 地 | 純黒 `#000000`。色相を持たない。撮った写真が画面幅いっぱいの主役になる |
| 文 | **キャッチコピーを置かない。** 見出しは銘柄名そのもの。「宇宙は、味わいでできている。」を含む見出しを全廃 |
| グラデーション | `--grad` を全廃。**これがいちばんAIっぽさを出していた要素** |
| 色の担い手 | ボタン・見出し・罫線から色を抜く。**画面に出る色は必ずスタイルを表している**状態にする |
| 形 | 一覧・推薦リストの左は **●**(帯は使わない) |

### スタイル色の二段構え

| グループ | 通常(減彩) | 強調(現行値) |
|---|---|---|
| IPA系 | `#86adbd` | `#5fd0ff` |
| Pale / Amber | `#c0b088` | `#ffd06b` |
| Stout / 黒 | `#a396b8` | `#b98cff` |
| 小麦 / Weizen | `#aeb890` | `#c8e86a` |
| Sour | `#bf96a8` | `#ff6fb0` |
| Lager / その他 | `#88b8ab` | `#5cf0c2` |

**強調を使ってよいのは3か所だけ**で、それ以外は減彩:

1. 同定された1本の写真の背後に灯るハロー
2. 一覧で絞り込み中・選択中のスタイル(●が発光する)
3. スタイル詳細ページの、そのページ自身のスタイル

実装は `group_map()` を単一の出所に保ったまま、各グループに2値を持たせる
(`['#86adbd', '#5fd0ff', 'IPA系']`)。色の出所が1か所という現行の性質は壊さない。

## 12. 公開まわり

| | 決定 |
|---|---|
| **AdSense** | `head.php` のタグを削除し、`privacy.php` から AdSense の行を消す。`ads.txt` と AdSense アカウントは残す(放置。料金もペナルティも発生しない) |
| **夜間停止** | いったん元どおり戻す(`seisan3-sleep` を ENABLED)。**ただし AWS CLI が未復旧のため実行は保留**。節約額が本当に月240〜280円かを Cost Explorer で実測してから、恒久停止(24時間稼働)に切り替える |
| **アフィリエイト** | 入れない。代わりに `official_url` を**蔵の直販ページ**に向ける(無報酬)。「うちは中立で、売上はあなたに返す」が蔵への売り文句になる |
| **公開の仕方** | dev で完成させ、**prod のトップを差し替える**。別URLでの先行公開はしない(蔵への営業より先にユーザー獲得が要るため) |
| **年齢確認** | 初回訪問時に1画面(「20歳以上ですか」)。選択は記憶し以後出さない。記憶先は**訪問者IDと一緒にサーバ側にも持たせる**(Safari のローカル保存は7日で消えるため) |

### 夜間停止を恒久的に止めるべき理由(実測後に判断)

1. **蔵のサイトに貼るウィジェットが夜間に壊れて見える。** 他社のページに埋め込むものが
   毎晩6時間落ちるのは商品として成立しない
2. 飲んだ直後に写真を撮る時間帯(1:00〜6:50)と重なる
3. Googlebot に 5xx を返す。Search Console から実際に
   「サーバーエラー(5xx)でインデックスに登録されない」通知が来ている

### 利用規約(新設)

| 項目 | 書くこと |
|---|---|
| アップロード画像 | 保存すること、**銘柄判定のため Anthropic に送ること**、公開面には一切出さないこと、削除の求め方 |
| 推薦の性質 | 推定であって保証ではない |
| PR枠 | 掲載料を受け取った枠であること、推薦順位には影響しないこと |
| 禁止事項 | 大量アップロード、ビール以外の投稿、他人の権利を侵す画像 |
| 免責・準拠法 | 一般的な条項 |

`privacy.php`(改正電気通信事業法の外部送信規律)には
**送信先: Anthropic PBC / 目的: アップロード画像からの銘柄判定 / 送信するもの: 画像**
を新しく書き足す。Google Analytics の行はそのまま残す。

## 13-b. 計画1を終えて、計画2に持ち越すもの

計画1(中核)の実装とレビューで確定した宿題。**上ほど急ぐ。**

### 公開前に必ず塞ぐもの

| | 何が問題か |
|---|---|
| **`img/upload/` が外から見える** | `.htaccess` は**一度も効いていない**。nginx は Apache に proxy しているので Apache が読む立場にいるが **`AllowOverride None`**(`deploy/nginx/drtbeer.conf` のコメントに明記)。加えて mod_autoindex が既定で有効なら**ディレクトリ一覧に全利用者の写真が出る**。`robots.txt` の除外は入れたが、それは検索避けであって遮断ではない。nginx に `location ^~ /img/upload/` を置くか、docroot の外へ出して PHP 経由で本人にだけ配る |
| **`vendor/` を docroot 直下に配っている** | SDK の `examples/*.php` 29本が直接リクエスト可能。いずれも `vendor/autoload.php` が無く致命エラーで止まるので即座の実害は無いが、公開面に第三者のコードを 16MB 置いている。`location ^~ /vendor/ { return 404; }` か docroot 外へ |
| **`api_config.local.php` が docroot 直下** | PHP ハンドラが落ちたときに平文配信される。中身は**課金に直結する鍵**。`location ~ \.local\.php$ { return 404; }` |
| **`deploy.sh` が `img/upload` を chown していない** | `img/tmp` と `img/product` だけ。root 所有のままでは apache が書けず、**写真の保存が必ず失敗する** |
| **prod の GD 拡張が未確認** | `identify_shrink()` に必須 |
